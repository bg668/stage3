# Reviser 条目完整性修复

## 目标与边界

J07/J11 的 Reviewer 已给出明确修正，Reviser 也修正了关键事实，但遗漏原有 claims，导致整个候选被拒绝并回退。增强完整输出指令和程序生成的列表执行说明；不放宽权限、合并或证据保护，不修改 schema、skill、预算、重试及失败回退，不自动调用模型或改写历史结果。

## 实现

- Reviser 按程序计划执行全部已授权修订，重大问题仍决定是否触发；触发后包含有明确 fixes 的 minor 修订。未授权删除的原条目必须逐项保留，禁止隐式省略、合并或重排，新增项追加到末尾。
- 输入模板明确“返回完整最终结果；可以精简文字，不得省略条目”，路径始终按 Analyzer 原始零基编号解释。
- `render_revision_scope()` 继续使用现有 `RevisionPlan` 和权限路径，为 claims、artifacts、gaps、handoffs、material_needs 输出原始、删除、新增和最终数量，以及原条目和新增授权槽位到输出位置的映射。删除压缩输出位置，未改变原始授权编号。
- 保留 baseline-v1 名称，新角色内容自然产生新指纹；新运行使用独立目录。旧指令夹具保留，新 Reviser 使用独立预期，历史角色可由冻结原文重建。
