01

执行摘要

样本具备明显的信息窃取与后续执行能力：在密码列表互斥体已存在时，它从 No-IP DUC、Windows Credential Manager、RAS、LSA、Protected Storage 以及 Internet Explorer/Firefox 相关位置读取或尝试解密凭据和浏览器数据，并将部分结果写入临时目录中的固定文件。

样本同时包含多层持久化和跨进程执行机制，包括 Run/Policies\Explorer\Run、Active Setup、远程 PE 映射、远程内存写入和远程线程创建；这些能力足以支持高风险恶意判定。

环境探测分支会检查沙箱、虚拟机、调试器和特殊设备，并在相应配置开关启用且探测命中时终止进程；多组互斥体则控制收集、输入 hook 和持久化/宿主处理路径。

风险判断
风险重点在于对多类本机凭据的读取/解密尝试，以及可将 PE 数据写入其他进程并创建远程线程的执行链。Run、Active Setup 和文件删除路径进一步扩大了持久化与清理风险。处置时应优先隔离主机、保护凭据并核查相关注册表、临时目录和进程注入痕迹。
02

样本入口、配置与分支控制

样本如何初始化配置并决定进入不同能力路径？

核心判断
样本通过嵌入式资源配置、全局开关和多个互斥体选择收集、输入处理、持久化或宿主进程操作路径。

配置初始化从名称为 XX-XX-XX-XX、类型为 0xA 的模块资源读取数据，复制到内部缓冲区后按 ####@#### 分隔解析，最多处理约 101 个配置槽位。对非空且未满足比较条件的条目，程序逐字节执行 ^ 0xBC 变换；随后这些值被复制或转换到多个全局配置字段。当前材料只能确认配置解析和变换，不能确定字段分别控制哪些业务功能。

启动控制使用 _x_X_UPDATE_X_x_、_x_X_PASSWORDLIST_X_x_ 和 _x_X_BLOCKMOUSE_X_x_ 等互斥体区分实例和功能分支。sub_401F48 本身不会动态生成互斥体名称：输入非空时原样返回，输入为空时返回内部静态地址；另一路径使用带 _PERSIST 后缀的名称参与实例判定。

样本还可读取命令行、当前模块文件名、系统目录、Windows 目录、用户名及 ProgramFilesDir，并把部分结果交给内部处理函数或用于路径构造。这些行为本身属于环境输入和辅助定位，不能单独说明其最终用途。

在 off_40D210 不等于 2 或 1 的路径中，若 off_40D1B8 == 1，样本会从模块文件名取得数据，并与 dword_40F1E8 进行比较。比较不满足时调用 sub_405AD8 和 sub_40AFB0，随后终止进程；比较满足时则转入后续 fallback 路径。两个辅助函数的具体副作用未解析，因此只能确认该条件分支及退出行为，不能进一步确定 open 参数所代表的操作。

03

凭据与浏览器数据如何被收集并暂存

哪些本机敏感数据进入了样本的数据处理链？

高风险能力
样本访问多个凭据存储和浏览器数据源，并对部分数据执行 DPAPI、LSA 或 NSS/PK11 解密；至少部分结果会进入临时目录文件。

在 _x_X_PASSWORDLIST_X_x_ 已存在的分支中，程序调用七个收集 helper，并在各自结果复制到 dword_40F1EC 后非零时写入临时目录。已闭合的路径包括：从 HKLM\SOFTWARE\Vitalwerks\DUC 读取 No-IP 的 UserName 和 Password；通过 CredEnumerateA 查询 WindowsLive:name=* 凭据并将组合结果写入 xxxyyyzzz.dat；以及由 RAS helper 枚举拨号条目并读取用户名、密码字段。

RAS 路径还可在特定系统版本、回调标志和配置目录条件下读取 rasphone.pbk 中的 DialParamsUID，处理关联数据后写回当前 RAS 条目的密码字段；另一分支通过当前用户名生成 SID 相关键，并读取 L$_RasDefaultCredentials#0 等 LSA 私有数据。Protected Storage 路径枚举包含 :StringData 的记录，解析字段并将处理结果提交到内部状态。

Internet Explorer 路径枚举 URL History，并读取 HKCU\Software\Microsoft\Internet Explorer\IntelliForms\Storage2 中的值；在 CryptUnprotectData 成功时，将记录整理为 User: 或 Password: 字段。Credential Manager 路径则使用由固定 GUID abe2869f-9b47-4cd9-a358-c22904dba7f7 派生的 74 字节可选熵尝试解密 CredentialBlob，再提取 Address、User 和 Password 结果。

Firefox 路径加载 nss3.dll 并解析 NSS/PK11 入口，读取 Profile0/Path 后依次检查 signons3.txt、signons2.txt、signons1.txt 和 signons.txt。当前材料已确认候选文件的打开、读入、Base64 解码和 PK11SDR_Decrypt 成功分支，但尚不能把所有返回数据确定为成功解密的凭据，也不能确认每个目标环境都能完成读取。

收集结果的外部输出并未全部闭合。已直接观察到的固定暂存文件包括 NOIP.abc、MSN.abc、FIREFOX.abc、IELOGIN.abc、IEPASS.abc、IEAUTO.abc、IEWEB.abc、xxxyyyzzz.dat，以及由配置组装后尝试写入的 XX--XX--XX.txt。各 helper 的调用和写入门控不等同于运行时写入成功。

04

输入 hook 与消息处理

样本是否记录或阻断用户输入？

认定边界
样本在特定互斥体条件下注册两个系统 hook；现有代码足以证明 hook 注册尝试和一个键盘转换调用，但不足以认定为键盘记录器或确认输入被阻断。

当密码列表互斥体未命中、而 _x_X_BLOCKMOUSE_X_x_ 已存在时，程序调用 SetWindowsHookExA 注册 hook ID 13 和 14，随后循环调用辅助函数直至其返回非零并退出进程。一个回调在 n256 == 256 时读取键盘状态并调用 ToAscii，另一个回调直接返回 1；当前代码未显示转换结果被保存、写文件或发送。

轮询 helper 从当前线程消息队列取出消息，非 WM_QUIT 消息进入 TranslateMessage 和 DispatchMessageA，之后短暂睡眠并继续处理，直到一次没有消息。该消息循环与 hook 注册存在调用关系，但没有证据表明它本身完成输入记录或阻断。

05

持久化、文件操作与宿主准备

样本如何保持运行或准备目标文件与目录？

持久化能力
样本具备多种持久化位置写入能力，并可创建目录、复制文件和设置 Active Setup；其中部分主 helper 的具体数据内容仍未解析。

在开关启用时，程序针对 HKLM 和 HKCU 的 Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\Run 以及 HKLM/HKCU 的 Software\Microsoft\Windows\CurrentVersion\Run 调用注册表处理逻辑。附加分支明确调用 RegCreateKeyA 和 RegSetValueExA 写入 REG 类型 2 数据；未解析的 sub_406088 是否在主调用中实施相同写入，当前不能完全确认。

Active Setup 流程先删除当前用户 Installed Components 下的指定子键，再在 HKLM 下创建对应组件并设置 StubPath；数据由输入字符串追加固定的 Restart 构成。另一路径在 v6 条件满足时调用未解析的执行相关 helper，随后终止当前进程，因此不能进一步断言其一定启动或执行文件。

样本可按路径逐级调用 CreateDirectoryA 创建缺失目录；另有复制分支根据构造出的候选路径调用 CopyFileA，首次复制失败时尝试备用目标。具体源文件、目标路径和后续用途未闭合，静态代码只证明复制与目录创建尝试。

06

跨进程映射与远程线程执行

样本如何把代码或数据转入其他进程？

关键执行能力
样本包含完整度较高的远程内存写入、PE 重定位/导入处理和远程线程原语，可针对 explorer.exe 或其他由配置选择的应用进程执行映射尝试。

当 off_40D210 == 2 且 explorer.exe 宿主条件满足时，程序定位 Shell_TrayWnd 所属进程，调用 VirtualAllocEx 和远程映像准备逻辑；若现有映射失败，则创建新的 explorer.exe 并再次尝试。若 explorer.exe 判断不满足，程序根据 sub_4064DC 结果选择应用路径数据，启动应用后交给同一映射例程。

远程映像准备包括按 PE 头分配映像和节区域、复制节数据、遍历重定位块并按基址差值修正目标地址；导入描述符和导入项也会被遍历，非零导入项通过远程辅助路径解析地址并回写导入表。sub_4038AC 在缓冲区有效时向目标进程写入数据并调用未解析的后续处理函数。

独立的远程线程原语先通过 VirtualAllocEx/WriteProcessMemory 写入参数和入口代码，再调用 CreateRemoteThread；同步模式还会等待线程并读取结果。另一路径将字符串、LoadLibraryA/Sleep 地址和间接调用结构写入目标进程；还有路径在目标进程中解析模块和导出符号，并以线程退出码返回地址。

_PERSIST 互斥体分支同样会检查 shell 宿主并在映射失败时创建 explorer.exe。另一路径向 Shell_TrayWnd 所属进程写入两块数据并尝试以 sub_40AE94 作为远程线程入口；该回调反复调用 DeleteFileA，直至删除调用返回非零。静态证据不证明远程线程、映射或删除最终成功。

07

反分析与环境探测

样本如何识别分析环境并改变流程？

反分析行为
多个独立配置开关分别控制沙箱、虚拟机、调试器、特殊设备和时间条件探测；命中对应探测后可直接终止进程。

探测集合包括检查 SbieDll.dll、枚举并匹配 VBoxService.exe、检查 dbghelp.dll、读取调试状态或 PEB 的 BeingDebugged 标志，以及探测 \\.\Syser、\\.\SyserDbgMsg、\\.\SyserBoot、\\.\SICE 和 \\.\NTICE。此外还有针对 ProductId、特殊设备和其他环境状态的独立 helper。

各探测分支分别要求自身开关为 1 且对应 helper 返回 1，随后调用 ExitProcess_0(0)；不能把这些分支合并为一个统一条件，也不能据静态代码断言目标环境必然命中。off_40D200 分支还会检查调试状态和超过 5000 毫秒的时间差，并修改加载模块链表相关字段。

其他已确认但用途未完全闭合的行为

哪些行为已观察到，但当前不能可靠归入主要目的？

辅助行为
样本还读取当前用户名并交给内部处理函数，生成配置组装结果并写入固定文件；这些行为的最终业务用途或外部去向尚未完全确定。

应急处置建议

  1. 1
    立即隔离并保护凭据将相关主机从网络和共享环境隔离，避免收集结果继续被使用；对浏览器、Windows Credential Manager、RAS、No-IP 和相关业务账户凭据执行轮换，并保留原始证据后再清理。
  2. 2
    排查持久化与注入痕迹核查 Run、Policies\Explorer\Run、Active Setup、临时目录固定文件、异常 explorer.exe/其他宿主进程、远程线程和跨进程内存写入记录；在确认取证完成后移除恶意持久化项。
  3. 3
    结合环境探测行为复核分析结果由于样本可在命中沙箱、虚拟机或调试器探测时退出，应将静态结论与终端遥测、注册表和文件系统时间线交叉核对，避免仅以未命中探测或未见写入成功否定其能力。
